# UI 美感

目标不是"加装饰"，而是**做减法后仍然清晰**。高级感来自克制、比例和一致性，不来自渐变、阴影和圆角。

写第一行样式前，先走完 §2 决策流程，得到一套 token；之后所有取值只能从 token 里取，不允许即兴写数字。

---

## 1. 九条铁律

1. **面积–彩度反比**：涂色面积越大，彩度必须越低。大背景 C≤0.012，卡片面 ≤0.02，色块 ≤0.06，控件 ≤0.19，小图标/徽标 ≤0.30。整屏最多 **一个** 强调色承担"注意力"，其余一律中性。
2. **间距成组**：间距表达从属关系，不是留白。同组元素 1 档，组间 2 档，区块间 3–4 档，页面级 8–12 档；**相邻档位比值 ≥1.5**，否则读者看不出分组。
3. **少即层级**：单页 ≤5 个字号、≤3 个字重、≤3 种圆角、≤3 级阴影。每多一个值，层级就弱一分。
4. **一种分隔手段**：边框 / 阴影 / 背景色差，三选一。同时用两种＝廉价感的第一来源。
5. **对齐轴**：整屏只允许 2–3 条垂直对齐线，所有文字左缘必须落在轴上（含嵌套层级）。
6. **视觉重量守恒**：想强调 A，就必须削弱 B。每个视觉区域只有一个主按钮、一个焦点。
7. **动效跟随距离**：位移越小越快。hover/开关 120–180ms，下拉/抽屉 200–260ms，页面级 280–400ms。入场 ease-out，出场 ease-in，位移动画方向与触发点一致。
8. **深色模式靠亮度不靠阴影**：暗色下阴影几乎不可见，抬升层级要**提高表面亮度**（每级 +0.035L）+ 描边。底不用纯黑（L 0.16–0.20），字不用纯白（L≤0.95）。
9. **光学修正**：嵌套圆角 = 外圆角 − 内边距；≥24px 字号收字距 −0.02em；图标视觉高度≈字符 cap height×1.2；纯几何居中的三角/播放键需手动右移。

## 2. 决策流程（必须先做）

### 2.1 业务场景 → 四轴人格

给场景在四个轴上各打 1–5 分：

| 轴 | 1 | 5 | 由什么决定 |
|---|---|---|---|
| **密度** density | 疏朗 | 紧凑 | 单屏信息量、使用时长。工具/高频＝高分，营销/低频＝低分 |
| **彩度** chroma | 冷静 | 鲜活 | 情绪诉求。金融医疗法律＝低，消费社交游戏＝高 |
| **柔和** softness | 锐利 | 圆润 | 亲和 vs 权威。奢侈品/专业工具＝低，儿童/生活服务＝高 |
| **重量** weight | 轻盈 | 厚重 | 信任 vs 时尚。银行/企业＝高，时尚/内容＝低 |

不确定就取该行业默认值，见 `references/personality.md`（含 8 类场景的完整 token 表：企业后台、数据分析、消费 App、营销落地页、内容阅读、电商、开发者工具、奢侈品/时尚）。

### 2.2 四轴 → token

- 密度 → 基础间距倍率、控件高度、行高
- 彩度 → accent chroma、中性色 tint 量
- 柔和 → 圆角阶梯
- 重量 → 字重、边框宽度、阴影强度、字号对比度

### 2.3 生成配色（不要手搓十六进制）

```bash
python3 scripts/palette.py ramp --hue 264 --chroma 0.16 --tint 0.006
```
输出中性色阶 + accent 色阶 + 语义色（success/warning/danger/info），全部已做 sRGB 色域收敛。`--tint` 让中性色微微偏向主色相——这是画面"整"的关键，纯灰会显脏。

## 3. 硬数值速查（已实测，非估计）

**对比度**（脚本实测，页面底 L0.985 / 暗色底 L0.175）

| 用途 | 浅色模式 | 深色模式 |
|---|---|---|
| 正文 AA 4.5:1 | 文字 **L ≤ 0.55** | 文字 **L ≥ 0.585** |
| 次要/大字 3:1 | L ≤ 0.65 | L ≥ 0.49 |
| AAA 7:1 | L ≤ 0.45 | L ≥ 0.70 |

> **Accent 填充按钮配白字：L ≤ 0.57**。实测 C 从 0.10 到 0.19，阈值都是 0.57——**彩度对对比度几乎无影响，亮度才是唯一杠杆**。想要更艳的按钮，只能加彩度不能提亮度。

**间距**：4px 基准，取值 `2 4 8 12 16 24 32 48 64 96`。禁止出现 5/7/13/15/18 这类非阶梯值。

**圆角**：sharp `0/2/4` · default `4/8/12` · soft `8/12/16` · round `12/16/24`。嵌套时内圆角 = 外 − padding。

**字号**：工具类 body 13–14px、比例 1.125–1.2；通用 15–16px、1.2–1.25；阅读类 17–18px、1.25–1.333。行高：正文 1.5–1.65，标题 1.1–1.25，超大标题 1.05。

**触控**：触摸 ≥44×44，鼠标 ≥32×32。

**焦点环**：2px accent + 2px 底色间隔；需对底 ≥3:1（浅色底下 accent **L ≤ 0.65**）。禁止 `outline:none` 不补样式。

## 5. 交付前自检门

产出后逐条核对，任何一条不过就返工——**不要把不合格的 UI 交给用户再问要不要改**：

1. 字号 ≤5、字重 ≤3、圆角 ≤3、阴影 ≤3 种？
2. 大面积（背景/卡片面）彩度是否都在预算内？整屏是否只有一个强调色？
3. 每对文字/背景是否过 4.5:1（大字 3:1）？用 `palette.py check` 实测，不要目测。
4. 是否存在"边框＋阴影＋背景色差"同时出现的元素？
5. 所有文字左缘是否落在 2–3 条对齐轴上？
6. 间距是否全部来自阶梯值？相邻分组层级比值 ≥1.5？
7. 每个交互元素是否有 hover / focus-visible / active / disabled 四态？焦点环是否可见且达 3:1？
8. 深色模式：是否靠亮度分层而非阴影？底非纯黑、字非纯白？
9. 空态、加载态、错误态、超长文本、单条数据、100 条数据——是否都不塌？
10. 对照 `references/antipatterns.md` 过一遍 AI 味清单。

**报告时**：说明选了哪套人格预设及理由，列出实测对比度数字。不要声称"符合 WCAG"除非跑过脚本。
